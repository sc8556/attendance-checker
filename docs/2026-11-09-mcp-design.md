# MCP 서버 설계 메모 (2026-11-09)

`mcp_server.py`를 만들면서 정한 것을 적는 자리. 구현 과정에서 실제로 정한 근거만 적고, 그럴듯한 이유를 지어내지 않는다. 문체는 README와 같게(한국어 개조식, 줄표 없음).

## 작성자가 맡은 일

- 요구: 채용 시장을 보고 MCP 서버를 붙이자고 정함
- 판단: AI 코딩 도구가 제안한 구성을 검토해서 받아들임. 쓰기 도구는 제안받았어도 보안 위험 때문에 거절했을 것
- 확인: Claude Code에서 정상 질문과 기간 밖 질문을 직접 해 봄

구현과 세부 설계는 대부분 AI 코딩 도구가 제안했음. 아래 각 절에 누가 정했는지 함께 적음.

## 왜 MCP를 따로 뒀나

- 채용 공고와 업계에서 MCP 경험을 요구하는 것을 보고 붙임
- 이 시연에서는 필요해서가 아니라 방식을 보여 주려고 만든 것. 가짜 DB가 코드 옆에 있어서 AI 도구가 직접 SQL을 짜도 같은 답이 나옴
- 차이가 커지는 건 운영 상황. 자료가 서버 DB에 있고, 묻는 사람이 현업 담당자이고, AI가 자료를 잘못 읽거나 바꾸면 안 될 때

## 도구 4개를 고른 기준과 뺀 것

- 조회 도구 3개(`find_issues`, `employee_records`, `time_difference`)는 AI가 제안한 구성을 그대로 받아들임. 웹 앱 자연어 질문의 조회 3종(`queries.py`)과 같음
- `data_range`는 AI 도구가 조건을 정하기 전에 데이터 기간, 직원, 문제 종류 이름을 확인하는 용도

뺀 것 네 가지. 모두 AI가 제안했고 받아들임.

| 뺀 것 | 이유 |
|---|---|
| 자연어 질문 도구 | AI 도구가 이미 LLM이라 조건만 넣으면 됨. 자연어 해석은 웹 앱의 Ollama 경로가 맡음 |
| 쓰기 도구 | 읽기 전용 원칙. 아래 「읽기 전용과 행 수 상한을 둔 이유」 참고 |
| 원격 HTTP 연결 | 개인 PC 시연 범위라 stdio만 씀 |
| 도구 5개 넘기기 | 따로 따져 본 근거 없음 |

## 조건 검증을 nl_query와 공유한 이유

- 도구가 받은 조건을 AI(Ollama) 응답과 같은 JSON으로 만들어 `nl_query.ask()`에 넘김. 날짜 형식, 보유 기간, 직원 존재, 문제 종류 검사를 두 벌 만들지 않고 한 곳에서 함
- 그래서 결과가 경로마다 같음. 「10월 1일 퇴근 미태그」는 웹 화면, 자연어 질문, MCP 모두 0건이 아니라 기간 밖(`out_of_range`)으로 돌아옴(README 캡처)

## 읽기 전용과 행 수 상한을 둔 이유

- 읽기 전용 구성은 AI가 제안했음. 반대로 쓰기 도구를 제안받았다면 받아들이지 않았을 것. 직원 기록을 AI가 함부로 고치면 보안상 위험하기 때문
- 실제 보호는 SQLite를 `mode=ro`로 연 부분(`connect()`). 도구에 붙인 readOnlyHint는 AI 도구에게 읽기 전용이라고 알려 주는 표시일 뿐 실제로 막지는 않음
- 행 수 상한 `MAX_ROWS = 500`은 AI가 정한 숫자이고 따로 따져 보지 않음
- 지금 가짜 데이터는 직원 12명 × 평일 10일 = 120일 치라서 어떤 조회도 500행에 닿지 않음. 시연에서는 의미가 없고, 상한이 걸리는지는 테스트로만 확인함

## 테스트로 확인한 것과 못 한 것

확인한 것

- 자동 테스트 `tests/test_mcp_server.py` 27개. 정답 12건과 한 건씩 대조, 기간 밖·없는 직원·형식 오류 8가지가 조회 없이 `status`로 돌아오는지, DB가 실제로 읽기 전용인지, 행 수 상한이 걸리는지
- 작성자가 Claude Code에 등록해서 직접 질문해 봄. 정상 질문(9월 2일 퇴근 미태그)과 기간 밖 질문(10월 1일). README 캡처가 이때 것

못 한 것

- 자동 테스트는 도구 함수를 직접 부름. 실제 MCP 통신(stdio)을 거치는 자동 테스트는 없음
- 해서는 안 되는 요청(기록 지워 줘 등)을 Claude Code에 넣어 거절되는지 직접 확인하지 않음
- Claude Desktop 연결은 README에 방법만 적었고 해 보지 않음
- 테스트 79개를 작성자가 직접 돌려 보지 않음
- 코드 한 군데를 바꿔 테스트가 깨지는지 확인하지 않음
